# Project Constitution: World Cup 2026 Simulator

## 1. Technical Stack
- Language: TypeScript (ES6+) for the frontend; PHP 8.0+ for the predictions backend.
- UI Framework: React 19 (Vite)
- CSS: Vanilla CSS with custom properties (CSS variables) for modern theme tokens, flexbox/grid layout, and smooth animations.
- Icons: Lucide React for modern, vector iconography.
- Backend: PHP + MariaDB/MySQL for the Family Predictions / Bolão feature.
- Data Sources: Embedded team lists/rankings for the simulator; FIFA official JSON feed for automatic results sync in predictions.

## 2. Architectural Layering
- The application will be structured as a Single Page Application (SPA).
- **State Management**: React state hooks (`useState`, `useMemo`, `useEffect`) to store groups, match scores, 3rd place rankings, and knockout bracket state. Predictions state is fetched from and persisted to the PHP backend.
- **Data Models**:
  - `Team`: `{ id: string, name: string, code: string, group: string, rating: number }`
  - `Match`: `{ id: string, type: 'group' | 'knockout', home: string, away: string, homeScore: number | null, awayScore: number | null, group?: string, stage?: string, nextMatchId?: string, winner?: string }`
  - `GroupStandings`: `{ teamId: string, played: number, won: number, drawn: number, lost: number, gf: number, ga: number, gd: number, points: number }`
  - `PredictionGame`: `{ id: number, external_id: string, stage: string, group_letter: string | null, home_team_id, away_team_id, home_team_name, away_team_name, home_code, away_code, home_flag, away_flag, kickoff_utc: string, venue: string | null, is_open: boolean, started: boolean, result_home: number | null, result_away: number | null, my_prediction, predictions }`
  - `LeaderboardRow`: `{ player_name: string, total: number, predictions: number, games_scored: number }`

## 3. Naming Conventions
- React Components: PascalCase (e.g., `GroupCard`, `KnockoutBracket`, `PredictionsView`).
- Custom hooks: camelCase starting with `use` (e.g., `useLocalStorage`, `usePredictions`).
- Variables, functions, and files: camelCase (e.g., `calculateStandings`, `apiClient.ts`).
- PHP endpoints: snake_case files (e.g., `save_prediction.php`, `sync_results.php`).
- Database tables: snake_case plural (e.g., `predictions`, `sync_log`).
- CSS classes: kebab-case (e.g., `bracket-card`, `team-row`, `predictions-container`).

## 4. Design & Style Invariants
- High-end dark theme with sport accents (deep indigo/slate background, neon green, electric violet, gold).
- Pure CSS styling (no Tailwind CSS, for maximum styling flexibility and to keep CSS isolated in `index.css` and dedicated CSS files).
- Transitions and micro-animations on all interactive items (hover effects, card scaling, active state changes).
- Responsive layouts using CSS Flexbox and Grid.
- Confetti celebration upon crowning a champion.

## 5. Security & Accessibility Mandates
- Standard semantic HTML tags (`header`, `main`, `section`, `footer`, `nav`, `button`).
- **Simulator**: Fully local operation in the browser; team lists, rankings, and schedules are embedded directly and persisted to `localStorage`.
- **Predictions backend**:
  - Session authentication uses same-origin HttpOnly cookies; no JavaScript-accessible tokens.
  - Database credentials live in a secrets file outside the web root (`wc-sim-secrets.php`).
  - Predictions are locked at kick-off; users cannot change picks after a game starts.
  - Family authentication is shared-password based; player names are trust-based and self-typed.
  - Invite links are single-token, passwordless entry points that can be disabled or regenerated by an admin.
- The FIFA auto-sync feature fetches official results over HTTPS and only fills games whose result is still empty unless explicitly configured to overwrite.
